# Предрегистрация шага 69: ворота поиска по совпадению с правильным нулём -- до кода

Написано до кода нуля, до ворот и до прогонов. Механизм `CSEARCH` -- из шага 68, без изменений.

## 1. Откуда

Ворота шага 68 не пройдены. Мера совпадения ставит линии к A и B наверх и при настоящем
порядке, и в нуле «знак отчёта -- жребий». Объяснение малым окном проверено (окно 256) и
опровергнуто.

Нуль задавал не тот вопрос. Несёт ли вход знак порядка, решают вес LMS и отмирание на пробе.
Поиск должен лишь находить входы, чьи **моменты** совпадают с неожиданностью части. Для этого
правильный нуль: отчёт приходит в моменты, не связанные с событиями A и B.

## 2. Две поправки статистики -- найдены при разборе, до прогона

Обе поправки найдены по устройству статистики, не по данным ворот 68, и объявляются здесь до
нового прогона.

1. **Максимум из многих.** В шаге 68 бралась лучшая из ~8 линий к A. Даже без всякой связи
   максимум из 8 равномерных рангов имеет медиану `0.5^(1/8) ≈ 0.92`. Порог 0.90 был бы пройден
   жребием.
   - Теперь статистика -- **медиана рангов всех линий к A** (и отдельно к B) у части.
   - Нулевое ожидание -- 0.5.
2. **Лишние запаздывания.** Мера для линии (товар 3) -- максимум по 7 запаздываниям, для прочих
   товаров -- одно. Любая линия поэтому стоит выше датчиков просто числом проб.
   - Теперь линии к A и B ранжируются **среди всех годных линий** (товар 3) части.
   - Ранг среди всех кандидатов печатается рядом, для разбора. Он же показывает, насколько
     механизм вообще предпочитает линии.

## 3. Нуль по времени (`ORDERTSHUF=1`)

События A и B идут, как прежде. Отчёт Q приходит в каждом круге с вероятностью `1/13.5` (та же
частота, что у отчётов в пробе) и со знаком по жребию. Он не связан ни с моментами, ни с порядком
событий. При `ORDERTSHUF=0` движок побитово прежний (`id69.js`).

## 4. Ворота

`gate69.js`: мир `embryo.env` с `YOUTH=1000 DLINE=6 ORDER=1 CHIST=1 CSEARCH=0`, круг 80000,
свежие сиды 4601-4606. Два условия: **порядок** и **нуль по времени**.

Для каждой части Q с полным окном (32) считается:
- медиана процентиля рангов её линий к A среди её годных линий;
- то же для B.

По частям берётся медиана.

**Ворота пройдены**, если выполнены оба условия:
- в порядке обе медианы (A и B) не ниже 0.90;
- в нуле по времени обе ниже 0.75.

Если ворота не пройдены, основные прогоны не делаются.

## 5. Если ворота пройдены -- основные прогоны шага 68, без изменений

Всё по `PRE68_CSEARCH.md` §5-6. Сиды те же (4301-4312 батарея, 4401-4412 строка 8), они не
использовались ни в одном прогоне.

Условия:
- батарея -- Ю, ЮС, ЮЛС;
- строка 8 -- Ю, ЮС, ЮЛ, ЮЛС.

Правило приёмки и чтения -- §6 шага 68, дословно.

3. Основные прогоны -- как в §7 шага 68. ЮС -- строка 8 не выше потолка 0.755. ЮЛС -- 0.70-0.85.
