# Предрегистрация шага 64: линия задержки с поправкой паузы -- перепроверка по табло

Написано до кода и до прогонов.

## 1. Откуда

Шаг 61: линия задержки у синапса (`DLINE = 6`) не принята -- упала строка 0 по прежней
`H(30)`. Шаг 62 показал, что прежняя `H(30)` по сидам не повторяется (от −6 до 37). Шаг 63
заменил её статистикой А (отношение сумм по сидам, разброс 0.056). Решение шага 61 стоит
на шумной мере.

Кроме того, в шаге 61 я заставил историю линии в паузе **стоять**. Тогда отводы 1-6 всю
паузу подают один и тот же последний отрезок входа, как постоянный вход. Это вероятная
причина порчи, не проверенная (правило 21).

## 2. Поправка

В паузе история линии **сдвигается, как в жизни**. Отводы 1-6 берут прошлые значения, а в
историю входит то, что видят покупатели датчика в паузе (при `HOLD = 2` -- молчание, 0).
Так же, как в круге свободной активности. Больше ничего не меняется. При `DLINE = 0`
движок побитово прежний (проверяется против движка до шага 61).

## 3. Прогоны

Новые сиды 3801-3812. Батарея (с мерой строки 0 по статистике А) в двух условиях **на
одних сидах**: зародыш как есть (`DLINE = 0`) и зародыш с `DLINE = 6`.

## 4. Приёмка и чтение

- **Приёмка (правило 22):** в условии с `DLINE = 6` ни одна строка не теряет действующего
  статуса: 0, 2, 3 (путь В, 100 кругов, 1000 кругов), 4, 7 -- ЕСТЬ; 6 -- наполовину.
- **Описательно, парно по сидам:** строка 4 (`bits9`, число сидов с передатчиком, доля
  удержания канала 9) и строка 0 (`H(10)`, `H(30)`) -- с линиями и без.

Строка 8 здесь не проверяется. Шаг 61 показал, что канал Q линий не получает, а поправка
паузы этого не касается.

## 5. Предсказания

1. Тождественность при `DLINE = 0` -- да.
2. Табло с линиями не падает: строка 0 по статистике А -- около 0.85 и 0.6.
3. Строка 4 с линиями держится в большем числе сидов, чем без них (в шаге 61 -- 12 из 12).
