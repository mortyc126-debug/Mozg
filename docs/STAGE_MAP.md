# STAGE_MAP.md -- где находится проект

ПЕРЕСМОТРЕН 2026-09-14. См. PRINCIPLES.md.

## 0. Исправление предыдущей версии

Версия от 2026-09-13 сверяла модель с БИОЛОГИЧЕСКИМИ ВЕХАМИ
(замыкание нервной трубки, миграция нервного гребня, пролиферация
нейроэпителия), как если бы они были спецификацией. По принципам
проекта это НЕВЕРНАЯ постановка: биология -- источник функциональных
идей, а не спецификация реализации. Вопрос «воспроизводит ли модель
морфогенез 3-5 недели» заменяется на «выполняет ли модель ФУНКЦИЮ,
которую этот морфогенез несёт».

Биологический раздел прежней версии удалён как вводящий в заблуждение.
Фактическая часть (что в модели есть и чего нет) сохранена.

## 1. Что фактически есть в модели (по MODEL_SPEC + v0.12)

- 80 точечных агентов; позиции -- `rng.uniform(0,1,(80,2))`, ЗАДАНЫ
  извне и НЕИЗМЕННЫ на всём протяжении;
- появление группами по 8 каждые 0.5с, созревание за 1с;
- рост связей по расстоянию (d<0.25), контакты не удаляются (до v0.7);
- STDP-подобная пластичность, веса [0, 0.08];
- гомеостаз порога к 5 Гц, адаптация (tau=0.2с), рефрактерность 5мс;
- **задержки проведения** -- реализованы в v0.12 (`v12_delays.py`),
  побитовое тождество с прежней пробой при нулевой задержке;
- оборот связей: удаление+замена (v0.7+).

## 2. Требования как ФУНКЦИИ (а не как механизмы)

По PRINCIPLES.md п.3: требование называет, ЧТО должно происходить.
Механизм -- кандидат на исполнение, и он требованием не является.

| # | ФУНКЦИЯ (требование) | Статус |
|---|---|---|
| Ф1 | Активность возникает без внешнего входа | ВЫПОЛНЕНО |
| Ф2 | Активность согласована между элементами | ВЫПОЛНЕНО (v0.3, cyclic-shift) |
| Ф3 | Связи НЕОБХОДИМЫ для согласования | ВЫПОЛНЕНО (v0.3) |
| Ф4 | Есть коллективный ритм с внутренним масштабом | ВЫПОЛНЕНО (v0.3) |
| Ф5 | Активность ограничена, без разгона | ЧАСТИЧНО (несут адаптация и гомеостаз; торможения нет и не требуется) |
| Ф6 | Активность распространяется в пространстве | **НЕ ВЫПОЛНЕНО** (v0.12) |
| Ф7 | Картина активности меняется по ходу развития | ЧАСТИЧНО (v0.6) |
| Ф8 | Опыт оставляет след в связях | ВЫПОЛНЕНО (dW>0 на 36/36) |
| Ф9 | След даёт функциональное последствие | ВЫПОЛНЕНО (v0.11: +2-3 п.п. при жёстком сроке) |
| Ф10 | Элементы приобретают РАЗНЫЕ состояния | ЧАСТИЧНО (различия заданы расписанием появления, не возникают) |
| Ф11 | Возникают границы между областями | НЕ ВЫПОЛНЕНО |
| Ф12 | Возникает пространственная организация | **НЕ ВЫПОЛНЕНО** -- позиции ЗАДАНЫ, а не формируются |
| Ф13 | Геометрия меняется со временем | НЕ ВЫПОЛНЕНО (позиции неизменны) |
| Ф14 | Возникают специализированные области | НЕ ВЫПОЛНЕНО (в v0.4 сетка 2x2 НАВЯЗАНА, не возникла) |

Механизмы, которые НЕ являются требованиями (кандидаты на исполнение
функций): тормозная популяция, задержки проведения, типы клеток,
щелевые контакты. Задержки реализованы в v0.12 и функции Ф6 не дали --
показательный случай, зачем нужно различение.

## 3. Где проект на дорожной карте (PRINCIPLES.md п.4)

| # | Этап | Статус |
|---|---|---|
| 1 | формирует пространственную организацию | НЕТ -- позиции даны извне |
| 2 | создаёт разные состояния элементов | ЧАСТИЧНО -- различия навязаны расписанием |
| 3 | образует границы | НЕТ |
| 4 | формирует ткани | НЕТ |
| 5 | меняет геометрию | НЕТ -- позиции неизменны |
| 6 | создаёт специализированные области | НЕТ -- в v0.4 навязаны |
| 7 | образует коммуникационные сети | **ДА** -- ядро работы v0.1-v0.11 |
| 8 | развивает сенсорные системы | НЕТ -- вне scope до сих пор |
| 9 | формирует интеграционные структуры | НЕТ |
| 10 | перестраивает связи | **ДА** -- v0.7-v0.11, проработано глубоко |
| 11 | обучается взаимодействовать со средой | НЕТ -- среды нет |

**Главное наблюдение.** Выполнены пункты 7 и 10 -- и только они.
Это СЕРЕДИНА и КОНЕЦ последовательности. Пункты 1-6, создающие условия
для них, не сделаны вовсе. Проект начал не с начала.

Это согласуется с наблюдением автора: работа ушла вглубь одной функции
(связи и их перестройка) и не вернулась к остальным.

**Самое резкое следствие.** Пункт 1 -- первый и самый базовый -- сейчас
не просто не выполнен, а обойдён: пространственная организация
ВЫДАЁТСЯ системе готовой (`rng.uniform`). Для проекта, чья суть --
приход к сложному из простого, это означает, что стартовое состояние
сложнее, чем должно быть: система получает даром то, что обязана
построить.

## 4. Ближайший осмысленный шаг

Не продолжать вглубь пунктов 7 и 10 (они проработаны лучше остальных),
а закрыть разрыв в начале последовательности.

Минимальный проверяемый шаг для пункта 1: позиции не выдаются
готовыми, а ВОЗНИКАЮТ (деление агентов и локальные правила вместо
`rng.uniform`). Сравнение делается той же меркой, что уже выверена:
всё в модели остаётся прежним, меняется ТОЛЬКО происхождение позиций,
и измеряется, отличается ли получившаяся организация функционально от
равномерно случайной.

Контроль для такого сравнения уже существует и проверен -- перестановка
позиций из v0.12 (те же растры, переставленные координаты).
